# 后端涉及算法与实现总览

## 1. 通信与网络仿真相关算法

### 1.1 基于 NS-3 的离散事件仿真

后端底层基于 NS-3 的离散事件机制运行。其特点是：

- 所有链路变化、业务发送、观测更新、故障注入、恢复动作与评估采样都由事件调度触发
- 系统通过推进仿真时钟来驱动网络状态演化
- 这种机制天然适合描述无人机网络中的时变通信过程

### 1.2 多参数无线通信建模

在通信层面，后端显式使用了多种无线网络建模参数：

- 路径损耗指数 `pathLossExp`
- 接收灵敏度 `rxSens`
- 发射功率 `txPower`
- 噪声系数 `noiseFigure`
- Nakagami-m 衰落参数 `nakagamiM`
- MAC 最大重传次数 `macRetries`
- 业务负载 `trafficLoad`
- 干扰节点数量、速率、占空比

这些参数共同决定链路质量、吞吐、时延与投递率。

### 1.3 多信道资源分配与动态重配置

项目主题本身就是 UAV 资源分配，因此后端包含：

- 信道分配
- 速率调整
- 功率调整
- 邻居/中继切换
- 路由重构
- TDMA 时隙重分配

这些动作在合作模式中被用于网络恢复，在基础链路中也影响 QoS 指标。从方法性质看，这部分更偏启发式网络控制与资源调度，其目标是：

- 提高吞吐
- 降低时延
- 维持连通性
- 提升 PDR

具体实现上，当前后端已经明确落了几类算法：

第一，信道分配采用的是一种基于拓扑度排序的贪心干扰最小化算法。系统先按节点度数从高到低排序，优先给核心节点分配信道；然后对每个候选信道分别估计同频一跳干扰、两跳隐藏终端干扰和信道负载惩罚，最终选择总干扰功率最小的信道。这本质上是“度优先 + 干扰最小化”的贪心信道分配。

第二，功率控制采用的是 SINR 驱动闭环控制。系统会先计算每个节点到其邻居中的最差链路 SINR，再和当前速率所需的最低 SINR 门限比较；如果 SINR 不足就升功率，如果余量过大就降功率，以减少外部干扰。此外，算法还会根据 PDR 是否低于目标值进行额外补偿，并在邻居过多时加入密度惩罚。这相当于一种“最差链路约束 + QoS 反馈补偿”的自适应功率控制。

第三，速率控制采用的是基于 SINR 门限查表的自适应速率选择。系统先计算最差链路和最好链路的 SINR，再构造一个加权有效 SINR，然后依据 802.11a 的调制解调门限表直接映射到可支持的最大速率。如果 PDR 偏低或端到端时延过大，还会对有效 SINR 施加惩罚，从而主动降速率以提高传输可靠性。这是一种典型的 SINR 驱动 AMC 速率控制。

第四，恢复阶段的动态重配置不是单一动作，而是由一组可控动作组合实现，包括信道重分配、功率调整、速率调整，以及在合作恢复逻辑中的局部邻域修复和全局重平衡。这意味着系统在工程上采用的是“多动作启发式联合恢复”，而不是固定策略单点优化。

## 2. 场景与传播环境建模算法

### 2.1 场景预设与环境参数建模

后端支持多类场景：

- urban
- forest
- lake
- open-field

不同场景会改变传播与观测参数，例如：

- 阴影衰落
- NLOS 附加损耗
- 植被损耗
- 水面反射扰动
- 城市街谷影响
- 连通范围系数

因此，场景不是单纯标签，而是直接参与链路质量与网络表现计算。

具体实现上，后端首先会根据 `sceneType` 构造不同的基础环境预设。`urban` 使用更强的阴影衰落、更高的 NLOS 惩罚、更低的基础 LOS 概率和更小的连通范围，同时启用建筑场景、城市低空附加损耗和街谷因子；`forest` 使用显式植被损耗率，并提高散射和链路不稳定性；`lake` 则启用水面反射感知、较低阴影衰落、更高 LOS 概率、更大的连通范围，并引入波动抖动、深衰落概率和反射时延抖动；`open-field` 则作为相对中性的基准场景。

在此基础上，系统还会叠加难度倍率。也就是说，同一个场景下，`Easy`、`Hard` 并不是只改一个名字，而是会进一步放大或减弱阴影衰落、NLOS 惩罚、干扰强度和连通范围。这使场景建模实际上变成了“场景 preset + 难度倍率”的二级建模。

除了传播参数，非合作观测参数也会按场景区分实现。比如 `urban` 的观测距离更短、随机丢失率更高、位置和功率噪声更大；`forest` 的观测也更难，但需要保留足够检测供后续推理；`lake` 的观测距离更远、丢失率更低、噪声更小；`open-field` 则处于中间水平。因此，同一套推理算法在不同场景下的输入质量实际上是不同的。

进一步说，后端对场景差异并不只停留在 preset 常数层面，还接入了额外环境修正。森林场景会根据林区特征估计植被损耗；湖面场景会引入反射敏感修正、波动抖动和深衰落；城市场景会根据相对高度施加低空惩罚或高空增益。也就是说，这一部分是“基础场景参数 + 额外环境修正 + 观测参数差异化”的组合实现。

## 3. 非合作观测算法

### 3.1 被动观测与轨迹生成

非合作模式下，系统不会直接使用敌方真实拓扑做推理，而是先通过被动观测形成观测轨迹与窗口活动。

### 3.2 时间窗口离散化与状态序列构造

系统将观测时间切成固定窗口，并进一步划分为多个子时隙。这样做的作用是：

- 把连续通信过程离散化为可分析时间序列
- 为后续因果和响应分析提供统一时间基准

在每个窗口内，如果目标在某个子时隙内被检测到，则该子时隙标记为 `1`，否则标记为 `0`，最终形成：

- `stateSequence`
- `activeRatio`
- `txCount`
- `txDuration`

其中 `stateSequence` 是后续拓扑推理的核心输入之一。

### 3.3 轨迹稳定性判定

系统不会因为单次检测就直接确认目标，而是通过连续观测窗口来维护轨迹稳定性。这一步的作用是：

- 抑制偶发误检
- 减弱短时丢失的影响
- 为后续推理提供更稳定的输入

## 4. 非合作拓扑推理算法

非合作拓扑推理是当前后端算法中最核心的一部分。整体流程是：

1. 由窗口观测构造候选边证据
2. 计算边的相关性与方向性因果分数
3. 进行多观察者证据融合
4. 结合时间连续性形成后验边概率
5. 进行伪边抑制
6. 输出最终推理边

### 4.1 基于状态重叠的共现边证据与多观察者融合

系统首先比较两个节点在同一观察者窗口中的 `stateSequence`，计算其时序重叠程度。其基本思想是：

- 如果两个节点在窗口内活动时序较一致
- 则它们更可能存在直接或间接通信关系

对于同一条候选边，不同观察者都可能给出证据。后端会融合这些证据，形成：

- `observerCount`
- `observerAgreementScore`
- `edgeObservationConfidence`

这意味着边推理不是基于单一视角，而是基于多观察者一致性进行加权判断。

### 4.2 因果型边推理：三类轻量方向性分数

这一部分是当前非合作拓扑推理中最值得重点讲解的内容。后端没有直接采用严格统计版因果检验，而是实现了三类轻量化的方向性因果分数，并将其接入边推理主链。

第一类是 Granger-like 滞后预测分数 `laggedPredictiveScore`。其核心思想是：如果 A 在前一个时间步活跃时，B 在当前时间步活跃的概率更高，则 A 对 B 具有更强的滞后预测能力。这借鉴了格兰杰因果分析的核心思想，但不是完整统计检验版，因此准确说法是“Granger-like 工程近似”。

第二类是 Transfer-Entropy-like 非对称响应分数 `directedResponseScore`。其核心思想是：当 A 从不活跃变为活跃后，B 是否会在短时延范围内响应，并且这一响应概率是否高于 B 的基线活跃率。这强调的是方向性响应，而不是简单同时出现，因此更接近转移熵思想的工程近似。

第三类是 Hawkes-like 事件激发分数 `excitationScore`。其核心思想是：A 活动之后，B 在接下来若干时间桶中更容易活动，而且越近的时间延迟权重越高。这对应事件激发强度建模，借鉴了多维 Hawkes 过程思想，但没有做完整参数学习。

### 4.3 边方向性、边概率融合与时间连续性更新

在得到上述因果分数后，系统进一步构造：

- `directionalityScore`
- `dominantDirection`

这样一来，推理结果不再只是“无向相关边”，而是带有方向倾向的动态边。

随后，系统会将以下因素按固定权重融合：

- 共现证据强度
- 观察者一致性
- 观测置信度
- 观察覆盖度
- 节点支持度
- 滞后预测分数
- 响应分数
- 激发分数
- 方向性分数

最终得到：

- `edgeProbability`
- `edgeConfidence`

此外，系统不会把每个窗口当成完全独立的静态问题，而是结合上一窗口边概率更新当前窗口后验。这种时间连续性更新的作用是降低边概率抖动、提高动态图稳定性，使推理结果更贴近真实连续演化过程。

### 4.4 边动态状态识别与伪边抑制

系统会基于后验概率和持续时间，给每条边打上动态状态标签：

- `stable`
- `emerging`
- `weakening`
- `vanished`

这让最终拓扑不仅包含“是否存在边”，还包含“边处于什么演化状态”。

同时，后端对推理边进行了两阶段伪边过滤。第一阶段是基础规则过滤，例如置信度过低、因果支持过低、连续性不足或动态状态已经消失；第二阶段是条件性抑制，即如果一条边可被更强的两跳路径解释，且其直接因果支持不足，则把它判定为可能的共享原因或间接路径伪边。

## 5. 图节点与关键节点识别算法

### 5.1 图节点摘要与多中心性结构特征

系统先从最终推理边构造图节点摘要：

- incidentEdgeCount
- weightedDegreeScore
- avgIncidentProbability
- avgIncidentConfidence

这是将边推理结果向节点层汇总的第一步。

在当前增强版推荐逻辑中，系统显式计算了多种图结构指标：

- 加权度中心性
- 加权介数中心性
- 加权接近中心性
- PageRank
- K-shell

这些算法用于识别：

- 高连接节点
- 路径桥接节点
- 拓扑中心节点
- 传播影响大节点
- 网络核心层节点

### 5.2 方向性影响力、时间稳定性与局部结构风险

系统在关键节点识别中并不只关心结构位置，还计算节点在有向因果边上的影响力。其本质是：

- 如果某节点在很多边上更像信息发出源
- 且该方向性具有较强因果支持
- 则其风险与关键性更高

同时，关键节点评分还考虑节点关联边的时间连续性和后验稳定程度，以减少短时异常高活跃节点被误判为关键节点的问题。

此外，系统还使用了若干局部结构风险特征：

- `localBridgeScore`
- `postRemovalDamageScore`
- `twoHopReachabilityScore`
- `interClusterBridgeScore`
- `localCutRiskScore`
- `neighborRedundancyPenalty`

这些指标本质上是在衡量节点的桥接性、删点破坏性、局部割裂风险和结构冗余程度。

### 5.3 多特征关键节点融合推荐

最终的非合作攻击推荐不是单指标排序，而是融合以下信息：

- 结构中心性
- 边证据支持
- 因果支持
- 方向影响力
- 时间稳定性
- 局部桥接
- 删除后破坏性
- 两跳可达性
- 跨簇桥接能力
- 局部切断风险
- 冗余惩罚

因此它本质上是一个用于关键节点识别和攻击推荐的多特征图融合排序算法。

## 7. 合作模式涉及算法

### 7.1 故障注入算法

合作模式支持多种故障：

- 节点故障
- 环境退化
- 外部干扰
- 链路退化

这些故障并不是只在配置层做区分，而是在后端中以不同作用机理接入：

- `node_failure`：目标节点被视为失效节点，接口被拉 down，并从有效合作节点集合中移除
- `environment_degradation`：目标相关链路的额外路径损耗增加，通信范围收缩
- `external_interference`：目标节点及其邻域接收额外外部干扰
- `link_degradation`：目标节点周围优先链路被定向退化，额外路径损耗更高
